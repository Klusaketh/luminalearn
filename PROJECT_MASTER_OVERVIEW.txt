1. EXECUTIVE SUMMARY & VISION
--------------------------------------------------------------------------------
LuminaLearn AI is an enterprise-grade, AI-first adaptive learning ecosystem 
designed to revolutionize online education.

The Problem:
Traditional Learning Management Systems (LMS) such as Coursera or Udemy deliver 
static, linear video courses. They treat all learners identically, regardless of 
aptitude, pace, or background. Students get stuck, experience cognitive overload, 
or lose engagement.

The Solution:
LuminaLearn AI continuously diagnoses each learner's cognitive pace, conceptual 
gaps, and preferred VARK learning modality (Visual, Auditory, Read/Write, 
Kinesthetic) to construct a 100% personalized learning trajectory.

Core Pillars:
1. Socratic AI Agent Framework: Never gives away direct answers. Guides learners 
   through scaffolded step-by-step questioning, hint ladders, and conceptual 
   self-discovery.
2. Cognitive Personalization (VARK Adapters): Dynamically calibrates content 
   presentation (visual diagrams, audio summaries, structured text breakdowns, 
   or interactive simulations).
3. Resilient Hybrid Infrastructure: Engineered with zero-downtime local fallback 
   mechanisms (SQLite + In-Memory Caching) alongside enterprise PostgreSQL + Redis.
4. Universal Accessibility (WCAG 2.1 AAA): Native architecture designed for screen 
   readers, high-contrast modes, dyslexia-friendly typography, and multi-modal 
   speech interfaces.
5. Explainable AI (XAI) & Learning Analytics: Transparent student mastery mapping, 
   decay curves (Ebbinghaus spacing effect), and retention forecasts for students, 
   parents, and educators.

3. COMPREHENSIVE INVENTORY OF COMPLETED WORK
--------------------------------------------------------------------------------
3.1. Adaptive Zero-Downtime Resilience Engine
- Cross-Database ORM (backend/app/core/database.py):
  Connects to PostgreSQL 16 by default via asyncpg. Automatically falls back to 
  embedded SQLite (luminalearn.db) when PostgreSQL is unreachable or USE_SQLITE=true.
  Uses sqlalchemy.Uuid(as_uuid=True) which compiles to UUID on PostgreSQL and 
  CHAR(32)/VARCHAR(36) on SQLite.
- Resilient Cache Client (backend/app/core/redis.py):
  Connects to Redis 7.2+. Automatically falls back to a thread-safe Python dictionary 
  cache with microsecond TTL expiration handling if Redis is offline.

3.2. Full-Stack Identity, Authentication & Security
- JWT Token Pair System (backend/app/api/v1/auth.py):
  Issues 15-minute Access Tokens and 7-day Refresh Tokens. Passwords hashed using 
  Argon2id/Bcrypt. HTTP-Only secure cookies and Authorization: Bearer support.
- Email OTP Verification System:
  6-digit numeric OTP generation stored as keyed HMAC-SHA256 hashes (never plaintext).
  10-minute expiration TTL, 60-second resend cooldown timer, 5-attempt brute-force limit.
- Google OAuth Integration (backend/app/api/v1/auth.py):
  Server-side cryptographic token validation using Google's public certs.
  Development mock modal for testing without a Google Cloud Console client ID.
- Role-Based Access Control (RBAC):
  User roles: student, teacher, admin. require_role(...) dependency injection.

3.3. Diagnostic VARK Cognitive Onboarding Subsystem
- 16-question diagnostic questionnaire evaluating learner preferences across Visual, 
  Auditory, Read/Write, and Kinesthetic axes.
- Stores student pace preference, academic interests, and modality scores in StudentProfile.

3.4. Academic Content Hierarchy Engine
- 5-tier relational structure: Category -> Subject -> Course -> Module -> Topic -> Lesson.
- Master Academic Content Seeder (scripts/seed_academic_content.py):
  Over 2,980 lines of rich academic content across 4 Disciplines, 22 Subjects, 
  22 Courses, 146 Modules, 165 Topics, and 12 Lessons.
- Academic API Endpoints (backend/app/api/v1/content.py):
  Filters by category slug, difficulty, and search. Verified email access guards.

3.5. Adaptive Quizzing & Bayesian Knowledge Tracing (Sprint 1)
- Database Schema (backend/app/models/quiz.py):
  QuizSession, QuizQuestion, QuizAttempt, StudentTopicMastery.
  Unique constraint uq_session_question_user_attempt enforces strict idempotency.
- Bayesian Knowledge Tracing (BKT) Engine (ml/models/knowledge_tracer.py):
  Real-time posterior mastery probability calculation:
  * If Correct:   P(Lt|Corr) = [P(Lt-1) * (1-P(S))] / [P(Lt-1)*(1-P(S)) + (1-P(Lt-1))*P(G)]
  * If Incorrect: P(Lt|Incorr) = [P(Lt-1) * P(S)] / [P(Lt-1)*P(S) + (1-P(Lt-1))*(1-P(G))]
  * Transition:   P(Lt+1) = P(Lt) + (1 - P(Lt)) * P(T)
- Item Response Theory (IRT 2PL Model):
  P(correct|theta) = 1 / (1 + exp(-a * (theta - b))) with numerical overflow guards.

3.7. Multi-Agent Socratic Faculty & Real-Time Voice (Sprint 2)

- Supervisor + 4 specialists (ai/agents/): Socratic Tutor (3-tier hint ladder, never gives

- WS /api/v1/voice/session: full-duplex voice with barge-in (interrupt cancels in-flight
  generation and TTS immediately; stale audio frames are dropped by turn id).
- Ebbinghaus retention forecaster (ml/models/retention_forecaster.py); quiz mastery radar.
- Frontend: Aurora design system, canvas voice orb, live tutor workspace, quiz overhaul.

3.8. Private Workspace & Connection Hardening
- Same-origin API: the browser calls the frontend's /api/v1 only; a Next.js route handler
  proxies it to BACKEND_URL (a rewrite carries the voice WebSocket). No API address in client
  code, no CORS, and a stopped backend returns one clear 503 instead of "Failed to fetch".
- Sign-in required for the whole workspace (everything except /, /login, /register/*,
  password reset and email verification): edge middleware redirects with a safe return path,
  a client gate verifies the session, and the API enforces it on tutor, voice (token in the
  first frame, close code 4401), catalog and onboarding routes.
- Session engine: one shared session check and one shared refresh (refresh tokens are
  single-use), renewal just before the 15-minute access token expires, retry once on 401,
  tabs kept in sync, and no sign-out when the server is merely unreachable.
- Loops closed: refresh bounce through /login, ?redirect=/login ping-pong, cached prefetch
  redirects after sign-in (full page load at sign-in/out), double navigation after Google
  sign-in, refresh-on-401 recursion (auth calls never auto-refresh), voice turns that crashed
  and left the orb "thinking" forever.
- Port guard: `python -m app` refuses a busy BACKEND_PORT, and a running server logs an error
  when another program answers on its port (Splunk owns 8000 on this machine).
- `npm run dev` at the repo root starts backend and frontend on matching ports.
- Reconnect banner probes the server with backoff; pages showing a load error reload by
  themselves when it returns.

7. QUICKSTART COMMANDS
--------------------------------------------------------------------------------
Start Everything (from the project root; Ctrl+C stops both):
  npm run dev
  -> API http://127.0.0.1:8001, web app http://localhost:3000 (or the next free port)

Or Start Separately:
  cd backend
  .\.venv\Scripts\Activate.ps1
  python -m app        (BACKEND_PORT from backend/.env; refuses a port already in use)
  cd ../frontend
  npm run dev          (its /api/v1 proxy forwards to BACKEND_URL in frontend/.env.local)
  Never run uvicorn on 8000 here: the Splunk service answers on that port.

Run All Backend Tests:
  cd backend
  pytest -v

Run Linter & Typecheck:
  cd backend
  ruff check .
  mypy app
