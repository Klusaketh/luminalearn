Data structures and algorithms is the study of how to organise data so that the operations a program needs are fast, and how to design step-by-step procedures that solve problems correctly and efficiently. Every serious program depends on it: a search engine ranking pages, a navigation app finding a route, a database answering a query, or a compiler allocating registers.

This subject builds the toolkit in a deliberate order. It starts with the language of efficiency, asymptotic analysis, so that you can compare solutions without running them. It then works through the core structures (arrays, strings, linked lists, stacks, queues, hash tables, trees, heaps, tries, and graphs) and explains for each one how it is laid out in memory, what it costs, and when to choose it. The second half turns to algorithm design: searching and sorting, recursion and backtracking, greedy strategies, divide and conquer, dynamic programming, and the classic graph algorithms for traversal, shortest paths, and minimum spanning trees.

Every lesson pairs theory with traced examples and runnable Python code, so you see both why an algorithm is correct and exactly what it does on a concrete input.

## What you will learn
- Analyse the time and space complexity of algorithms using Big-O, Big-Omega, and Big-Theta notation
- Choose an appropriate data structure for a problem by comparing the cost of its operations
- Implement and trace linked lists, stacks, queues, hash tables, binary search trees, heaps, and tries
- Apply searching and sorting algorithms and explain their complexity, stability, and trade-offs
- Design algorithms with recursion, backtracking, greedy choice, divide and conquer, and dynamic programming
- Represent graphs and solve traversal, shortest-path, and minimum-spanning-tree problems
- Argue that an algorithm is correct using loop invariants and induction

## Prerequisites
- Comfort with one programming language; the examples use Python
- Basic algebra, including exponents and logarithms
- Familiarity with proof by induction helps for the analysis sections

## Glossary
- **Algorithm**: a finite, unambiguous sequence of steps that solves a problem for every valid input
- **Data structure**: a way of organising data in memory together with the operations it supports
- **Abstract data type (ADT)**: a specification of operations and their behaviour, independent of any implementation
- **Asymptotic complexity**: how an algorithm's resource use grows as the input size tends to infinity
- **Big-O**: an asymptotic upper bound on a function's growth, up to a constant factor
- **Amortized cost**: the average cost per operation over a worst-case sequence of operations
- **Invariant**: a property that holds before and after every step of a loop or operation
- **Stable sort**: a sort that keeps equal elements in their original relative order
- **Hash function**: a function that maps keys to array indices for constant-time average lookup
- **Load factor**: the ratio of stored keys to available slots in a hash table
- **Balanced tree**: a tree whose height stays logarithmic in the number of nodes
- **Heap property**: in a min-heap, every node is no greater than its children
- **Graph**: a set of vertices connected by edges, possibly directed or weighted
- **Greedy algorithm**: one that makes the locally best choice at each step without revisiting it
- **Dynamic programming**: solving a problem by combining solutions to overlapping subproblems, each computed once
- **Backtracking**: building a solution incrementally and abandoning a partial solution as soon as it cannot succeed
