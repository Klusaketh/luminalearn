## Introduction

Some questions about linked lists seem to need extra memory or two passes. Where is the middle? Does the list loop back on itself? If it loops, where does the loop start? A straightforward answer might count the nodes first, or store every visited node in a set.

The **fast and slow pointer** technique answers all of these in one pass with only two extra variables. A *slow* pointer moves one step at a time while a *fast* pointer moves two. Their relative motion carries information: when the fast pointer reaches the end, the slow one is in the middle; if the fast pointer ever catches up with the slow one, there must be a cycle. The cycle-detection version is known as **Floyd's tortoise and hare** algorithm.

**Before you start:** you should be comfortable with singly linked lists and basic modular arithmetic.

## Core theory

### Finding the middle

Start both pointers at the head. In each step, move `slow` one node and `fast` two nodes. Stop when `fast` cannot move two steps. Since `fast` has travelled twice as far, `slow` is halfway.

- For an odd number of nodes, `slow` lands exactly on the middle node.
- For an even number, the stopping condition decides which of the two middle nodes you get. With the loop `while fast and fast.next`, `slow` ends at the **second** middle; with `while fast.next and fast.next.next`, it ends at the **first**.

Time is $\Theta(n)$ and extra space is $\Theta(1)$.

### Finding the $k$-th node from the end

A variant uses a fixed gap instead of a speed difference: advance `lead` by $k$ nodes first, then move `lead` and `trail` together one step at a time. When `lead` falls off the end, `trail` is $k$ nodes from the end. This finds, for example, the node to remove in "delete the $k$-th node from the end" in one pass.

### Detecting a cycle: Floyd's algorithm

A list has a **cycle** if following `next` pointers eventually revisits a node, so traversal never reaches `None`. Floyd's algorithm moves `slow` one step and `fast` two steps:

- If `fast` reaches `None`, the list has an end, so there is no cycle.
- If the list has a cycle, both pointers eventually enter it. Once both are inside, measure the distance from `slow` forward to `fast` around the cycle. Each step, `fast` gains exactly one node on `slow`, so the distance shrinks by one, modulo the cycle length. It must therefore reach zero within one lap: the pointers **meet**.

Because the fast pointer cannot "jump over" the slow one (the gap changes by exactly one each step), meeting is guaranteed. The algorithm uses $\Theta(1)$ space, compared with $\Theta(n)$ for remembering visited nodes in a set.

### Finding where the cycle begins

Let $\mu$ be the number of steps from the head to the first node of the cycle, and $\lambda$ the cycle length. Suppose the pointers meet $k$ steps into the cycle (measured from its first node), after `slow` has taken $s$ steps. Then:

- `slow` has travelled $s = \mu + k + a\lambda$ for some number of laps $a \ge 0$,
- `fast` has travelled $2s = \mu + k + b\lambda$ for some $b > a$.

Subtracting, $s = (b - a)\lambda$: the slow pointer's distance is a multiple of the cycle length. So $\mu + k$ is a multiple of $\lambda$, which means that walking $\mu$ more steps from the meeting point lands exactly on the start of the cycle (after $\mu$ steps you have gone $\mu + k$ steps into the cycle, a whole number of laps).

That gives the second phase: move one pointer back to the head, keep the other at the meeting point, and advance both **one step at a time**. After exactly $\mu$ steps they meet at the first node of the cycle.

To find the cycle length $\lambda$, keep one pointer fixed at any node in the cycle and walk the other around until it returns, counting steps.

### Beyond linked lists

The technique works on any sequence where each element determines the next, $x_{i+1} = f(x_i)$, such as repeated application of a function on a finite set. Such a sequence must eventually repeat, forming a "rho" shape: a tail of length $\mu$ leading into a cycle of length $\lambda$. Floyd's algorithm finds $\mu$ and $\lambda$ in $O(\mu + \lambda)$ time without storing past values. Pollard's rho factorisation algorithm and detecting loops in pseudorandom number generators use exactly this idea.

## Worked examples

### Example 1: Middle node

```python
class Node:
    def __init__(self, value, next=None):
        self.value, self.next = value, next

def build(values):
    head = None
    for v in reversed(values):
        head = Node(v, head)
    return head

def middle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow.value

print(middle(build([1, 2, 3, 4, 5])))
print(middle(build([1, 2, 3, 4, 5, 6])))
```

Output:

```text
3
4
```

With five nodes, `fast` visits 1, 3, 5 and stops; `slow` visits 1, 2, 3. With six nodes, `fast` visits 1, 3, 5, then moves to `None` (past 6), and `slow` advances to 4, the second of the two middle nodes.

### Example 2: Detecting a cycle and finding its start

```python
class Node:
    def __init__(self, value):
        self.value, self.next = value, None

def make_rho(tail_len, cycle_len):
    nodes = [Node(i) for i in range(tail_len + cycle_len)]
    for a, b in zip(nodes, nodes[1:]):
        a.next = b
    nodes[-1].next = nodes[tail_len]        # close the loop
    return nodes[0]

def cycle_info(head):
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:                    # phase 1: they met
            break
    else:
        return None                         # fast reached the end
    slow = head                             # phase 2: find the start
    mu = 0
    while slow is not fast:
        slow, fast = slow.next, fast.next
        mu += 1
    lam, runner = 1, slow.next              # phase 3: measure the loop
    while runner is not slow:
        runner, lam = runner.next, lam + 1
    return slow.value, mu, lam

print(cycle_info(make_rho(3, 5)))
print(cycle_info(make_rho(0, 4)))
```

Output:

```text
(3, 3, 5)
(0, 0, 4)
```

For a tail of 3 nodes leading into a cycle of 5, the algorithm reports that the cycle starts at node 3, after $\mu = 3$ steps, and has length $\lambda = 5$. When the whole list is a cycle, the start is the head and $\mu = 0$. No set of visited nodes was needed.

### Example 3: Repeated states of a function

The happy-number problem asks whether repeatedly replacing a number by the sum of the squares of its digits eventually reaches 1. Otherwise the sequence falls into a cycle that never contains 1.

```python
def next_value(n):
    return sum(int(d) ** 2 for d in str(n))

def is_happy(n):
    slow = fast = n
    while True:
        slow = next_value(slow)
        fast = next_value(next_value(fast))
        if fast == 1:
            return True
        if slow == fast:
            return False

print([n for n in range(1, 25) if is_happy(n)])
```

Output:

```text
[1, 7, 10, 13, 19, 23]
```

There is no linked list here, just a function from numbers to numbers. The sequence must eventually repeat, because the values quickly fall below a fixed bound. If it reaches 1 (which maps to itself), the number is happy. If `slow` and `fast` meet elsewhere, the sequence is stuck in a cycle that avoids 1. For example, 4 leads to 16, 37, 58, 89, 145, 42, 20, and back to 4.

## Applications

- **Memory leak and corruption detection.** A corrupted linked structure that accidentally loops would make naive traversal hang; Floyd's algorithm detects it safely.
- **Garbage collectors and graph tools** use cycle detection on reference chains.
- **Cryptography and number theory.** Pollard's rho algorithm for integer factorisation and discrete logarithms uses Floyd-style cycle finding on pseudorandom sequences.
- **Pseudorandom generators.** Measuring the period of a generator's state sequence is a cycle-length problem.
- **Interview and examination problems:** middle of a list, palindrome linked list (find the middle, reverse the second half), remove the $k$-th node from the end, and duplicate detection in an array whose values point to indices.

## Common mistakes

- **Checking `fast.next.next` without checking `fast.next`,** which raises an error on lists of even length.
- **Moving `fast` two steps in phase 2.** When locating the cycle start, both pointers must move one step at a time.
- **Comparing values instead of node identity.** Two different nodes can hold equal values; use `is` (identity) when detecting cycles in linked lists.
- **Forgetting the empty and single-node cases.** Start with checks that `head` and `head.next` exist where the algorithm needs them.
- **Assuming the meeting point is the cycle start.** The first meeting is generally somewhere inside the cycle; phase 2 is required to find the start.

## Revision notes

- Slow moves 1, fast moves 2. When fast reaches the end, slow is at the middle (second middle with `while fast and fast.next`).
- $k$-th from the end: give the leader a head start of $k$, then move both together.
- Floyd: if there is a cycle, fast gains 1 node per step inside it, so the pointers must meet within one lap.
- Cycle start: reset one pointer to the head, move both one step at a time; they meet at the start after $\mu$ steps.
- Cycle length: walk around from a node in the cycle until you return.
- Works for any sequence $x_{i+1} = f(x_i)$; $O(\mu + \lambda)$ time, $O(1)$ space.

## Practice questions

:::question basic
For the list `10 → 20 → 30 → 40`, which node does `middle` from Example 1 return, and why?
:::answer
It returns 30. Initially both pointers are at 10. After one step slow is at 20 and fast at 30. Since fast.next (40) exists, another step moves slow to 30 and fast to `None` (past 40). The loop condition fails, so slow is at 30, the second of the two middle nodes.
:::

:::question basic
Why does Floyd's algorithm use only $O(1)$ extra space while the obvious alternative uses $O(n)$?
:::answer
The alternative stores every visited node in a set and reports a cycle when a node is seen twice, which can grow to $n$ entries. Floyd's algorithm stores only two pointers, regardless of the list length, and detects a cycle by their meeting.
:::

:::question intermediate
Describe how to remove the 2nd node from the end of a singly linked list in one pass, and handle the case where that node is the head.
:::answer
Create a sentinel whose `next` is the head, and start both `lead` and `trail` at the sentinel. Move `lead` forward $k + 1 = 3$ nodes. Then move `lead` and `trail` together, one node at a time, until `lead` becomes `None`. Now `trail` is the node immediately before the target, so remove it with `trail.next = trail.next.next` and return `sentinel.next`. In a list of length $n$, `trail` ends $n - k - 1$ nodes after the sentinel, which is exactly the predecessor of the $k$-th node from the end. If the target is the head (for example $n = 2$), `lead` reaches `None` during its head start, `trail` never leaves the sentinel, and the same line removes the head.
:::

:::question intermediate
In a list with a tail of length $\mu = 4$ leading into a cycle of length $\lambda = 6$, how many steps does phase 2 of the cycle-start algorithm take, and where do the pointers meet?
:::answer
Phase 2 takes exactly $\mu = 4$ steps, and the pointers meet at the first node of the cycle (the node 4 steps from the head). This follows from the fact that the distance from the meeting point to the cycle start, going forward, equals $\mu$ modulo $\lambda$.
:::

:::question intermediate
Is 2 a happy number? Use the sequence of digit-square sums to justify your answer.
:::answer
No. Starting from 2: 4, 16, 37, 58, 89, 145, 42, 20, 4, and so on. The sequence enters the cycle 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4, which never reaches 1, so 2 is not happy. Floyd's algorithm would detect this when the slow and fast values become equal inside that cycle.
:::

:::question advanced
Prove that in Floyd's algorithm, once both pointers are inside a cycle of length $\lambda$, they meet within at most $\lambda$ further steps.
:::answer
Let $d$ be the number of steps the fast pointer is behind the slow pointer, measured forward around the cycle, with $0 \le d < \lambda$. In each step the slow pointer moves 1 and the fast pointer moves 2, so the gap shrinks by exactly 1: $d \to d - 1$. Because it decreases by exactly one each time, it cannot skip past zero; after $d \le \lambda - 1$ steps it is zero and the pointers occupy the same node. So they meet within fewer than $\lambda$ steps of both entering the cycle.
:::
